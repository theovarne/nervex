# WEB–SOMA Interface

WEB–SOMA is the production site's **experimental visual research interface**. Its deployed runtime and attributed media are present in site/; third-party assets retain their own licenses.

| Layer | Meaning | Provenance |
| --- | --- | --- |
| SOMA | Synthetic arachnid body / visual reference | BIOLOGICAL REFERENCE |
| CNS | Integration-region morphology reference | BIOLOGICAL REFERENCE |
| WEB | Computational external sensory topology | COMPUTATIONAL / SIMULATED |
| SIGNAL | Animated propagation of observed or simulated events | Must be tagged per event |
| GLOBAL | Network-wide view | Mixed; each datum requires a source tag |
| PERSONAL | User-approved wallet-centered view | LIVE / SOLANA if obtained from RPC |

The site supports orbit controls, layer switching, node selection, thread interaction, and inspector updates. These interactions demonstrate an architectural model. A rotating spider or vibrating thread does not establish a biologically derived trading algorithm.

The site combines references from different spider taxa: a body morphology source and an Uloborus diversus CNS atlas. They are not presented as one biological specimen. In research documentation, BIOLOGICAL, COMPUTATIONAL, LIVE / SOLANA, EXTERNAL MARKET, and SIMULATED RESEARCH labels must remain separate.

When WebGL or a model asset fails, interfaces should report that state without inventing live values. The current page shell has a Framer-derived lineage; a future independent implementation could replace it without changing the Solana/provider model.
